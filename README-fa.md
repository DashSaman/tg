# TG — تانل شخصی ایران به خارج

**نسخه ۰٫۱ نمونه اجرایی با آزمون محلی است. سرعت ۳۰۰ مگابیت و پایداری در شبکه واقعی
ایران هنوز تأیید نشده‌اند.** هدف اول حداقل ۳۰۰ مگابیت بر ثانیه ترافیک مفید دریافتیِ
تجمیعی است؛ هدف ۱۰ گیگابیت به مرحله بعد و سنجش ظرفیت مسیر و سخت‌افزار مربوط است.

**آزمون محلی با WireGuard معیار ۳۰۰ مگابیت را رد کرد:** در ۳۰ دقیقه ترافیک TCP با
هشت اتصال، میانگین گیرنده ۱۹۹٫۷۶ و کمترین پنجره ده‌ثانیه‌ای ۷۴٫۱۹ مگابیت بود.
حافظه خود TG در این بار رشد پیوسته قابل‌توجهی نداشت. جزئیات و روش تکرار در
[گزارش WireGuard](docs/wireguard-validation.md) ثبت شده است.

دو حامل مستقل QUIC روی UDP و HTTPS/2 روی TCP احراز هویت و رمزنگاری دارند. پایش هر
دو ادامه دارد؛ مسیر بدون پاسخ از انتخاب خارج می‌شود و بازگشت به مسیر بهتر به چند
نمونه تازه و زمان انتظار نیاز دارد. تأخیر، نوسان RTT و فشار صف در انتخاب دخیل‌اند.
سوکت برنامه در خارج با تغییر حامل ثابت می‌ماند. صف و بازسازی قطعات محدود هستند.

این نسخه یک برنامه UDP را میان دو سرور حمل می‌کند. برای عبور IP و ترافیک کاربران،
WireGuard لایه داخلی است و جداگانه تنظیم می‌شود. TG رابط WireGuard، مسیر، فایروال
یا NAT ایجاد نمی‌کند. کد تانل‌های دیگر کپی نشده؛ کار اختصاصی پروژه لایه نشست و
مدیریت حامل‌هاست، نه ادعای اختراع QUIC یا چندمسیره بودن.

با Go نسخه ۱٫۲۶ یا بالاتر:

```sh
go build -trimpath -o bin/tg ./cmd/tg
./bin/tg init --dir lab --server-name localhost
./bin/tg check --config lab/exit.json
./bin/tg check --config lab/edge.json
```

سپس در دو ترمینال جدا:

```sh
./bin/tg run --config lab/exit.json
./bin/tg run --config lab/edge.json
```

تنظیم پیش‌فرض محلی است: ورودی edge روی UDP پورت ۳۱۸۲۰ و مقصد exit روی UDP پورت
۵۱۸۲۰. مقصد باید برنامه پاسخ‌دهنده یا WireGuard داشته باشد. پوشه آزمایش محرمانه
است؛ آن را منتشر نکن. کلید CA را آفلاین نگه دار و روی هر میزبان فقط کلید خودش را بگذار.

آزمون TLS، رد توکن و هویت اشتباه، قطع و بازیابی UDP، جایگزینی با HTTPS، ثابت ماندن
سوکت خروجی، راه‌اندازی دوباره همتا، حذف تکرار و ظرفیت صف در مخزن هستند. پایش فعلی
رفت‌وبرگشت حامل را می‌سنجد، نه سلامت کامل اینترنت خروجی یا جیتر برنامه. دو حامل روی
یک IP در برابر مسدود شدن همان IP مستقل نیستند. QUIC قابل تشخیص است و HTTPS/2 تضمین
عبور از DPI نیست.

`t6` خصوصی و [GoldWaterTunnel](https://github.com/DashSaman/GoldWaterTunnel) بررسی شدند؛
فقط درس‌های عمومی طراحی از t6 منتقل شده‌اند. IP spoofing گزینه تحقیقاتی مشروط به
آزمون مسیر دوطرفه است؛ در این نسخه پیاده نشده. FEC، REALITY/XHTTP، تجمیع ظرفیت
چند مسیر و مهاجرت بدون افت بسته نیز ادعا نمی‌شوند.
